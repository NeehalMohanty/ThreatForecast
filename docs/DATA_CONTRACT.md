# Telemetry contract

`POST /api/predict`: one numeric feature object. `POST /api/predict/batch`: `{"network_data": [ ... ]}`. `POST /api/analyses`: same plus `"source": "synthetic_demo"` or `"imported_telemetry"`, saves the report. `GET /api/analyses?limit=50` reads summaries. Interactive schema: `/docs`.

Supply normalized CICIoT23 features; see `backend/schemas.py` for all fields. Network counters and measurements must be finite and non-negative; trends may be negative. Magnitudes over 1e15 are rejected. Unknown fields are rejected to catch spelling mistakes. `magnitude` and `magnitue` are accepted aliases; use only one. At least one of `flow_duration`, `header_length`, `protocol_type`, `rate`, `tot_size` must be explicitly supplied. This minimal acceptance threshold does not establish that an input is representative.

The 46 classifier features should ideally all be supplied. Omitted features are filled with zero and enumerated in `missing_features`. This may cause unreliable classifications. Behaviour fields such as `failed_logins` or `privilege_changes` must come from observed telemetry, not inferred from unrelated packet counters. Empty input is never accepted as a benign observation.

CSV import accepts a simple header row and numeric cells, 1–100 rows and at most 1 MB. Headers are trimmed, lowercased, and spaces/hyphens converted to underscores. Remove label, IP and timestamp columns from this independent-row inference input. Arbitrary quoted text CSV and raw PCAP/Zeek/Suricata formats are not supported. Use JSON for structured numeric input. Batches are independent records, not a time series.

Results use percentage units (0–100) for classifier confidence and transition scores. The latter are normalized heuristic weights, not calibrated attack probabilities. `risk_score` is a severity index. `forecast_window` does not provide elapsed-time lead time. `predicted_attack` describes the current proxy classification; it is not a claim that the next event will be malicious.

Version 2.1 propagates the full classifier distribution through the transition rules: next-state weight is the sum of each current state's classifier weight multiplied by its behaviour-adjusted transition weight. `current_stage_probabilities` exposes the classifier distribution. `uncertainty.margin` is the top-two difference in percentage points; `uncertainty.entropy` is normalized entropy (0–1), with larger values indicating more dispersed weights. Neither is an empirical error estimate. A margin below 10 points prompts an ambiguity warning; the threshold is a UI heuristic. `data_quality.coverage_percent` measures field presence only, not correctness, representativeness or sensor trust.

For future temporal training, `python -m ml.real_sequence_builder input.csv --output data/processed/observed_sequences.csv` requires `sequence_id,timestamp,stage` plus six genuinely observed behaviour fields. Timestamps must be parseable, unique within each sequence and refer to one consistent sampling strategy. Output uses current values, past-only differences, the following observed stage and actual interval in seconds. Partition entire campaigns before fitting any model. This builder does not train or activate a forecasting model.

Analysis reports contain results and source provenance, not raw submitted feature values. The latest 1,000 reports are retained; 50 are shown by default. Back up `data/runtime/analyses.db` with the service stopped, or back up the Docker named volume. Users on the same installation share these summaries; there is no account isolation.
